# Contributing

**Issues** (bugs, questions, ideas) are welcome, in English or Spanish: say which version you use, what you did and what you expected. For questions and
open-ended ideas, use [Discussions](https://github.com/NachoPola16/aldune/discussions).

Before sending a Pull Request, open an issue to talk about it: the project has design decisions documented in [docs/](docs/) (in Spanish for now;
`ROADMAP.md` records what was discarded and why, `STATUS.md` what is done) and the rules for anyone touching the code are below.

## Project rules

- **UI text** always goes through `Strings.T(en, es, de, fr, pt)` (`src/Aldune/Resources/Strings.cs`): all five languages, nothing hard-coded in XAML or code. On Android, strings live in `android/strings.tsv`
  (edit there and run `python android/scripts/gen_strings.py`).
- **New logic goes in `Aldune.Core`, test first.** The UI is verified with a throwaway probe ([docs/WPF_PROBES.md](docs/WPF_PROBES.md); Android: [docs/ANDROID_PROBES.md](docs/ANDROID_PROBES.md)).
- **Code comments are in Spanish** and explain the why (the code already says the what).
- **Colors** come from the palettes and themes (`AppPalette`, `NoteThemes`), never loose hex values in XAML. The logo and icons are generated by `scripts/branding/generar-iconos.py` and are never touched up by hand ([docs/BRANDING.md](docs/BRANDING.md)).
- **Never run the development build against `%LOCALAPPDATA%\Aldune`**: those are real notes. To test, use a temporary data folder (the `ALDUNE_DATA_DIR` environment variable).
- **Data compatibility**: an old `settings.json` must load without migration, and the sync format is not changed without thinking about the installed versions.
- Build and test: `dotnet build Aldune.slnx -c Debug` and `dotnet test Aldune.slnx --no-build` (Android: `./gradlew test` from `android/`, JDK 21).

## License of what you send

By sending code you agree that it is published under [GPL-3.0](LICENSE) and that the maintainer may **also redistribute it under other licenses**
(for example, for app stores). Sign your commits with `Signed-off-by` (Developer Certificate of Origin,
<https://developercertificate.org>): that confirms the code is yours or that you have the right to send it.

## What is not accepted without discussing it first

- Changes to the sync format (the format is 4; installed versions reject what they do not understand).
- Code that sends data off the device or adds telemetry, ads or trackers.
